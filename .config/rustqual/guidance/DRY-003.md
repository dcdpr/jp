The same run of statements appears in more than one production function.
The finding gives the number of statements and doesn't name the other places:
`just qual` lists every location of each fragment under `DRY / Dead Code`.

Fixes, in order:

1. Extract the statements into a function, when what they do together has a
   name and the copies would change together.
2. When the fragment is the tail or the head of two functions that are
   otherwise different, check whether one can call the other.

A few statements that are alike by coincidence, such as two unrelated builders
setting three fields, are not worth a helper.
Say that the finding is of this kind and leave the code.

Don't extract a helper that needs a flag to behave differently for each caller,
and don't reorder statements to make the match go away.

Marker, only when the user asks for one: `// qual:allow(dry, fragment) reason:
"…"` above each function that holds the fragment.

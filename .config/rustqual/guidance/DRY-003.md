The same sequence of statements appears in multiple production functions.
The finding reports only the statement count, not the other locations; run `just
qual` to list every occurrence of each fragment under `DRY / Dead Code`.

Fixes, in order:

1. Extract the shared statements into a helper function when they form a single
   logical step that should change together across call sites.
2. When the shared fragment is at the start or end of two functions, check
   whether one function can delegate to the other.

When a short sequence matches by coincidence (such as two unrelated builders
setting three fields), don't extract a helper; report the coincidental match and
leave the code as is.

Don't extract a helper that requires a mode flag to branch per caller, and don't
reorder statements just to evade detection.

No marker passes the gate for this rule.
`// qual:allow(dry, fragment)` suppresses the finding in the DRY pass, but the
main pass (`.config/rustqual/config.toml`) has fragment detection off and
reports the marker as stale (`ORPHAN-001`).

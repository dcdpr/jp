Production code calls this function, and no test reaches it.
A test reaches a function when it calls it, or calls something that calls it.

Fixes, in order:

1. Write a test that reaches the function through its real caller, and assert
   what that caller produces.
   Test the function directly only when it is the unit worth pinning, such as a
   parser or a pure calculation.
2. When the only caller is generated code (`#[serde(default = "…")]`,
   `serialize_with`, a clap value parser, a derive), test through that path:
   deserialize the input that takes the default and assert the result.
   rustqual can't follow such a call, so the finding stays after the test is
   written.
   Say so, and name the test.

Don't add a test that calls the function and asserts nothing about its caller's
behaviour, only to clear the finding.

Marker, only when the user asks for one, and only for case 2: `//
qual:allow(test_quality, untested) reason: "reached through serde; covered by
<test name>"` above the function.

A production function calls `.unwrap()` or `.expect()`, or invokes `panic!`,
`unreachable!`, or `todo!`.
Test functions are not checked.
The finding reports only a count, not which call or macro triggered it.

Fixes, in order:

1. Propagate the failure with `?` into the crate's typed error.
   Add a variant when none fits; don't stringify the error to make it fit.
2. For an `Option`, return an error with `.ok_or(…)?` or `let … else`.
3. Make the failure unrepresentable in the types: parse into a type that rejects
   invalid values, or replace `unreachable!` with an exhaustive `match`.

Don't replace `.unwrap()` with `.unwrap_or_default()` or `.ok()` to discard an
error the caller should see, and don't replace it with `.expect()`, which `A20`
also flags.

Marker, only when the user asks for one: `// qual:allow(complexity,
error_handling) reason: "…"` above the function.
Use this marker for a deliberate `.expect("…")` on an invariant that holds by
construction, and document the invariant in a `# Panics` section on the
function's doc comment.

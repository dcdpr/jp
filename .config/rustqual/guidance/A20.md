A production function calls `.unwrap()` or `.expect()`, or invokes `panic!`,
`unreachable!` or `todo!`.
Test functions are not checked.
The finding gives a count and doesn't say which of these it found.

Fixes, in order:

1. Propagate the failure with `?` into the crate's typed error.
   Add a variant when none fits; don't stringify the error to make it fit.
2. For an `Option`, return an error with `.ok_or(…)?` or `let … else`.
3. Make the failure impossible in the types: parse into a type that can't hold
   the bad value, or match exhaustively where `unreachable!` stood.

Don't swap `.unwrap()` for `.unwrap_or_default()` or `.ok()` to drop an error
the caller should see, and don't swap it for `.expect()`, which is counted the
same.

Marker, only when the user asks for one: `// qual:allow(complexity,
error_handling) reason: "…"` above the function.
It is the form for a deliberate `.expect("…")` on something that can't fail by
construction, which also needs a `# Panics` section in the function's doc
comment.

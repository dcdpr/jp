Cyclomatic complexity is over 10: the function has more than ten paths through
it, counting each `if`, loop and `match` arm.
The finding gives the score and not the limit.

Fixes, in order:

1. Split the function where it does two things, for example validating its
   input and then acting on it.
2. Move the handling of one `match` arm, or of one group of arms, into a
   function named for what it handles.
3. Replace a chain of `if` / `else if` on one value with a `match`, and merge
   the arms that do the same thing with `A | B =>`.

A flat `match` that only maps each variant to a value, such as a `Display` impl
for an enum with twelve variants, is over the limit and reads fine.
Don't restructure it to lower the score: say that the finding is of this kind.

Don't move branches into closures, and don't split the function into single-use
helpers that only make sense read in order.

Marker, only when the user asks for one: `// qual:allow(complexity,
max_cyclomatic=N) reason: "…"` above the function, with `N` at most 10% above
the current score.

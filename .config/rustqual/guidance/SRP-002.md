The file has more than 800 lines of production code.
Blank lines and comments don't count, and counting stops at the first
`#[cfg(test)]`, which is why that attribute belongs on the module declarations
at the end of a file and nowhere above them.
Test files have no limit.

Fixes, in order:

1. Split the file into child modules by responsibility, not by size: the types
   and functions that change together move together.
   A table of data, such as a model catalog, is the first thing to move.
2. Move each function whole.
   `qual diff` follows a moved item to its new file and keeps the baseline of
   its findings; a function left behind under its old name has them reported as
   new.

Don't split a file into `part1.rs` and `part2.rs`, don't move code into the
tests file to hide it from the count, and don't delete comments.

When the split doesn't belong in the change at hand, the file takes a pin and a
ticket, and only when the user asks for one: `// qual:allow(srp, file_length=N)
reason: "…; split in T-…"` on the first line of the file, with `N` at most 10%
above the current count.
The gate fails again once the file grows past `N`.

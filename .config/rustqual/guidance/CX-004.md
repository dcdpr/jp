The function is longer than the limit: 60 lines in production code, 150 in a
test function.
Every line from the opening brace to the closing one counts, comments and blank
lines included.
The finding gives the length and not the limit.

Fixes, in order:

1. Return early, so the main path isn't nested inside its preconditions.
2. Extract a step that does one job and has a name worth reading.
   A long `match` whose arms each do real work usually splits by arm.
3. For a long test, check whether it tests two behaviours, and make it two
   tests.
   Each test keeps its own setup: don't move setup into a shared fixture to
   save lines.

Don't split the function into a chain of single-use helpers that only make
sense read in order, don't delete comments or blank lines to get under the
limit, and don't touch code the change doesn't need.

Marker, only when the user asks for one: `// qual:allow(complexity,
max_function_lines=N) reason: "…"` above the function, with `N` at most 10%
above the current length.

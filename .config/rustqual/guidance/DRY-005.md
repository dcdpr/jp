Three or more `match` expressions, each with at least three arms, have the same
shape.
rustqual compares the shape alone: the matched type, the variant names, and the
values of literals don't count.
The type named in the finding comes from one `match` of the group, and the
finding doesn't name the other functions; run `just qual` to list them under
`DRY / Dead Code`.

Inspect the full group before refactoring.
When its functions match on the same enum, move the `match` into a method on the
enum (such as `Status::as_str` or `Kind::is_terminal`) and call that method from
each site.

When its functions match on different enums, the finding is a false positive.
For example, every `match` that maps the same number of unit variants to string
literals has the same shape.
Report the false positive and leave the code as is.

Don't combine `match` expressions that compute different properties into a
single method controlled by a mode parameter.

Marker, only when the user asks for one: `// qual:allow(dry, repeated_matches)
reason: "…"` at most three lines above the `match` keyword, which can mean
inside the function.
A marker further away is reported as stale (`ORPHAN-001`).
One marker suppresses the finding for every `match` in the group, not only the
one below it.

Three or more `match` expressions, each with at least three arms, have the same
shape.
The rule compares only the `match` structure, ignoring the matched type, variant
names, and literal values.
The type named in the finding is taken from one `match` in the group, and the
finding does not list the other functions; run `just qual` to list them under
`DRY / Dead Code`.

Inspect the full group before refactoring.
When the functions in the group match on the same enum, move the `match` into a
method on the enum (such as `Status::as_str` or `Kind::is_terminal`) and call
that method from each site.

When the functions match on different enums, the finding is a false positive.
For example, every `match` that maps the same number of unit variants to string
literals has the same shape.
Report the false positive and leave the code as is.

Don't combine `match` expressions that compute different properties into a
single method controlled by a mode parameter.

Marker, only when the user asks for one: `// qual:allow(dry, repeated_matches)
reason: "…"` within three lines above the `match` keyword (inside the function
body if the `match` is not at the top of the function).
A marker placed further above the `match` is reported as stale (`ORPHAN-001`).
Suppressing one `match` in a group suppresses the finding for the entire group.
